# Preview App Store and Google Play listings

## Show a store listing preview

Check your own renders with `get_preview_image`; showing them to the user is their choice. When a new set, reference match or requested edit is finished, summarise it and share the editor link, where the user may already be watching, then ask once how they want to see it here. Name only the forms this connection offers, for example: all pages as images, the interactive gallery, an App Store or Google Play listing preview, or side by side with the reference. Do not render or fetch images only to present them before the user answers. When the user asks to see the screenshots or picks a form, show them without another question, starting with the chosen size and language, and keep using that form for later previews. Images from `get_preview_image` reach you, but some clients hide them in tool calls, so present them using the client's image display mechanism. The editor link is additional, never a substitute for a preview the user asked to see.

Reuse completed previews that still match the saved pages and selected sizes and languages. A gallery shows only the images in its operation. If the work spans multiple operations, cover all relevant batches and make their page ranges clear. Follow `nextOffset` through contact sheets so no pages are omitted. Render only missing or changed outputs, or expired previews; opening a different view is not a reason to render again.

- **Interactive previews in chat:** when `show_preview_gallery` is available and supported by the client, use it when the user wants to see the set. Use `show_store_listing_preview` when the user asks how it will look in the store or picks a listing preview, a useful offer before export or upload. Pass the app name, subtitle, developer and category when you know them; empty details show placeholders. Reuse the completed preview operation. If the tools are unavailable or the client cannot display the view, show the images. A text acknowledgement is normal for these tools and does not mean the interactive view failed.
- **Images in chat:** reuse a suitable completed preview. If a render is needed, call `render_project_preview` and wait with `wait_for_operation` using `timeoutSeconds: 25` and the [35-second runner guidance](screenshot-copy.md#wait-efficiently). Use `get_preview_image` to inspect the images, and show them when the user wants to see them and no interactive view is available. Show a contact sheet as returned: one row per language and size, with pages left to right at the same height. These are rendered screenshot pages. If the user cannot see the images, give `get_artifact_link` links to the pages.
- **Browser listing preview:** when the user requests a listing in the browser, call `get_project`. Open its `storePreviewUrl` and choose the requested store screenshot size and language in **Preview & Export → Preview**. If the link opens on the canvas, open that tab manually. If a matching screenshot output is missing, offer chat images or ask before adding one. To open the standalone preview or add artwork, wait for the two phone previews, then choose **Preview a listing** below them. Confirm the new tab shows the selected project screenshots. The standalone tool has editable artwork and text fields. If you cannot use the signed-in editor, share the project preview link and those steps. Skip server render jobs, exports and screenshot downloads for this workflow.

The free [App Store screenshot preview](https://appscreens.com/app-store-screenshot-preview) lets users combine screenshots with an icon, listing text, App Store artwork or a Google Play feature graphic. Use the editor handoff for saved projects. Use the options below for images the customer already has.

- **Universal Creative Asset:** Add the original 5244 × 2950 PNG once under **Creative assets → Universal Creative Asset**. **Use for** defaults to **Both**, or choose **Header** or **Search**. Keep the original image intact and let the preview crop it. Use **Show safe area** to check the design. On a saved project, add the artwork in the standalone tab you already opened so the selected screenshots stay there.
- **Local files:** open the preview page and ask the user to drag the screenshots, icon and artwork onto it or add them with its file buttons. The files stay in their browser and are not uploaded.
- **Images on the web:** link to `https://appscreens.com/app-store-screenshot-preview#preview=` followed by the listing as base64url-encoded JSON, for example `{"platform":"apple","appName":"CookBook","subtitle":"Save recipes. Plan meals.","icon":"https://…","screenshots":["https://…","https://…"]}`. The fields are `platform` (`apple` or `google`), `view` (`search` or `detail`), `appName`, `subtitle`, `developer`, `category`, `rating`, `ratingCount`, `searchQuery`, `searchAd` (true for a search ad), `icon`, `searchArtwork`, `headerArtwork`, `universalArtwork`, `appleUniversalPlacement` (`both`, `header` or `search`) and up to 10 `screenshots` in listing order. Every image is an HTTPS link the customer already has. On Google Play, `searchArtwork` is the feature graphic and `subtitle` is the short description. Signed links stop loading when they expire, so say when that is. Images that can't load show in red on the preview page, and the user can select them to remove them. See the [listing preview examples](https://appscreens.com/developers/guides#listing-preview).

Side by side with a reference means the reference and result in the same page order at comparable display sizes. Say what you showed and any unresolved issues.
